# SITE14 Backend: database and tests

Express API with PostgreSQL through Prisma ORM 7. This file covers the database and test setup.

Owner: Faisal Alshahrani (Database Architecture / QA). Jira: SITE-69 (schema), SITE-75 (seed data).

The schema follows `Stage3.md` section 2.2: **16 tables and 1 view**, plus heart rate (v2.1).
The ER diagram is on the team Miro board ("Database Design v2.1").

## Files

| Path | What it is |
| --- | --- |
| `prisma/schema.prisma` | The 16 models, enums and relations. Prisma Client is generated from it. |
| `prisma/migrations/20261015000000_init/migration.sql` | The SQL that creates the database. Part 1 mirrors `schema.prisma`; Part 2 adds what Prisma cannot express (CHECKs, partial unique indexes, triggers, the view). |
| `prisma/seed.js` | Demo data: two companies, so tenant isolation can be seen. |
| `prisma.config.mjs` | Prisma 7 settings: schema path, migrations path, seed command, database URL. |
| `package.json` | Libraries, `npm run` commands, and the Jest settings (`jest` key). |
| `babel.config.js` | Lets Jest load the generated Prisma Client. Not used when the app runs. |
| `src/config/db.js` | The single Prisma Client used by the app (node-postgres driver adapter). |
| `src/generated/prisma/` | Generated by `npx prisma generate`. Not committed. |
| `tests/db/` | Database rule tests (plain SQL) and a round trip of all 16 models through Prisma. |

## First run

Requires Node.js 22.18 or newer and PostgreSQL 16 installed on your machine (no Docker).

On macOS with Homebrew:

```bash
brew install postgresql@16
brew services start postgresql@16
createdb site14_dev
createdb site14_test
```

(Postgres.app works too: start it, then run the two `createdb` lines.)

```bash
cd Portofolio/Backend
cp .env.example .env          # set YOUR_MAC_USER (whoami) and JWT_ACCESS_SECRET (openssl rand -hex 32)
npm install                   # also runs `prisma generate`
npm run db:deploy             # applies the migrations to site14_dev
npm run db:seed               # optional demo data
npm run dev                   # API on http://localhost:4000
npm test                      # 31 tests on site14_test
```

Demo logins after seeding: `admin@albina.test`, `manager@albina.test`, `admin@nadeef.test`, `manager@nadeef.test`, password = `SEED_PASSWORD` from `.env`.

## Commands

| Command | Use |
| --- | --- |
| `npm run db:deploy` | Apply pending migrations. Safe on shared databases. |
| `npm run db:migrate` | Development only: create a new migration after editing `schema.prisma`. |
| `npm run db:reset` | Development only: drop everything, re-apply migrations, re-seed. |
| `npm run db:seed` | Load the demo data. |
| `npm run db:studio` | Browse the data in Prisma Studio. |
| `npm run db:check` | Compare the live database with `schema.prisma`. See below. |

### Changing the schema

1. Edit `prisma/schema.prisma`.
2. `npm run db:migrate -- --create-only --name what_changed` writes a new migration without applying it.
3. Read the generated SQL. Add any CHECK, trigger or partial index by hand at the end.
4. `npm run db:deploy`, then `npm test`.

Never edit a migration that has already been applied on a shared database. Add a new one.

### `npm run db:check`

After `db:deploy`, this prints the SQL Prisma would run to make the database match `schema.prisma`.
Expected: empty, or only lines about the two partial unique indexes
(`work_sessions_one_open_per_employee`, `alerts_one_open_per_type_per_session`), which Prisma cannot model.
Anything else means `schema.prisma` and the migration disagree.

## Rules enforced by the database

| Rule | How | Error code |
| --- | --- | --- |
| A company only links to its own rows | Composite foreign keys with `company_id` | 23503 |
| No work session without the worker's consent | Trigger `require_consent` | RC002 |
| One open work session per worker | Partial unique index | 23505 |
| A reading sent twice is stored once | Unique `(session_id, recorded_at)` | 23505 |
| `telemetry_logs`, `record_corrections`, `reports` are append-only | Triggers reject UPDATE and DELETE | AO001 |
| Alerts keep their findings; only handling columns are filled, once | Trigger `alerts_handling_only` | AO001 |
| One open alert of each type per session | Partial unique index | 23505 |
| Each alert type carries its fields (zone, minutes, bpm) | CHECK | 23514 |
| Heart rate 20 to 250, battery 0 to 100, valid coordinates | CHECK | 23514 |
| Emails stored lower-case, so unique is case-insensitive | CHECK | 23514 |
| Nothing with history is deleted | `ON DELETE RESTRICT` | 23503 (23001 on PostgreSQL 18) |

Prisma reports a unique violation as `P2002`. Our own codes (RC002, AO001) arrive as the PostgreSQL error code inside the Prisma error.

## Differences from Stage3.md section 2.2

To be confirmed with Laila, then copied into `Stage3.md`.

1. **Heart rate** (new): `heart_rate_bpm` in `telemetry_logs` and `employee_current_state`; `limit_bpm`, `observed_bpm` in `alerts`; alert types `heart_rate_high`, `heart_rate_low`; thresholds `heart_rate_max_bpm`, `heart_rate_min_bpm` in `companies` (NULL = alert off). The Charter lists health monitoring as out of scope, so `Stage2.md` needs updating too.
2. `employees.consent_given_at` added (Charter item 7, missing from 2.2).
3. `users.failed_login_count`, `users.locked_until` added (used by the login lockout).
4. Repeated readings: unique `(session_id, recorded_at)` instead of "unique per device" (the table has no `device_id`).
5. Append-only by **triggers** instead of `REVOKE`: `REVOKE` does not bind the table owner, and the app connects as the owner.
6. Alerts may be updated, but only `acknowledged_by`, `acknowledged_at`, `resolved_at`, once each. Endpoint #43 needs this.
7. `employees.job_category` is a real foreign key to `job_category_rules (company_id, job_category)`.
8. `reports.mime_type`, `reports.file_size_bytes` added (school rule: file metadata in our database).
9. `record_corrections.site_id` added (the daily record is per worker, site and day).
10. Values chosen where 2.2 gave none: `employee_status` = active, inactive; `session_end_reason` = left_site, shift_ended, device_offline.
11. One open work session per worker (partial unique index), not stated in 2.2.
